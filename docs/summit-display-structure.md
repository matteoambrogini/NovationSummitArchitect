# Summit display structure — firmware 2.1

## Scope and source

This document records the display navigation observed in the complete supplied
video, not a reconstruction from isolated frames.

- Document: `Summit display/menu structure video`
- Section: complete `00:00–02:25` pass
- Local source: `docs/references/summit-ui/summit-ui-reference-pack/summit-display-menu-structure.mp4`
- Target firmware shown by the instrument: `2.1`
- Verified: `2026-07-27`
- Machine-readable model: `src/data/summit-display-structure.json`

The model deliberately separates:

1. parameter identity, range and semantics, which remain in
   `summit-parameter-catalog.json`;
2. observed display location, which lives in
   `summit-display-structure.json`;
3. OLED and setup rendering, which is generated by the UI.

No parameter identity is inferred from the display alone. A visible field without
a matching verified catalog identity remains explicitly unmapped.

The numbered areas contain 45 pages and 119 visible fields. Of those fields, 116
map to verified catalog parameters. `USER WAVES / Wave`, `USER WAVES / Save` and
`CLOCK / Status` remain unmapped: the first lacks a verified patch parameter
identity, the second is an action, and the third is runtime state.

MOD and FX MOD add 20 complete slots with four fields each. Their generic field
shape is recorded once per area and values come from the validated slot catalogs.

Settings is global instrument state and is intentionally excluded from patch
setup and patch-completeness calculations. Multi pages are also not traversed in
the supplied video; Multi patch data remains supported by the existing verified
catalog without presenting its page locations as video-observed.

## Conflicts resolved by the observed layer

The pre-existing menu catalog reports OSC as 8 pages, LFO as 8 pages and FX as 10
pages. The supplied firmware-2.1 recording shows 9, 10 and 9 pages respectively.
It also places the LFO 3 and LFO 4 waveform/rate fields on their own pages before
their phase/slew/fade pages. The display model records this observed navigation
without changing parameter semantics or erasing the documented conflicts in the
source catalog.

Setup instructions therefore use the observed display model first. Catalog-only
locations remain available as a safe fallback and are labelled accordingly.

## Rendering contract

- An area button opens page 1.
- A numbered page is reached with `PAGE >` exactly `page - 1` times.
- The field line comes from the display structure, not from the older catalog
  row value.
- Values always come from the active validated proposal and scope.
- Selecting a mapped field synchronizes the physical panel, OLED and inspector.
- Matrix areas render the complete 16-slot MOD or 4-slot FX MOD assignment set.
- Unmapped fields are visible but read-only and never enter generated patch setup.
